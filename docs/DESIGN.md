## 1. 结论先行

1. **这不是从零做，是给已完成的 surfcore 补一层壳。** 现有 `E:\AI\surfcore` 已是 v0.6.17：45 个 src 文件、148 个脚本（其中 97 个 `test-*.mjs`）、253 KB 控制台页、DSH 侧 14 标签设置页、39 个 `qq_*` 工具、3 个 MCP server。真正缺的只有四件：**泛化、安装向导、独立设置页、打包分发**。
2. **「全部打包进安装包」这个口径要改**。原稿是按「surfcore 是你自己的项目」写的；核实后它是**第三方项目**（`Mieksido/surfcore`，MIT，版权行为 `Copyright (c) 2026 Derpyu520 and qq-bridge / QSH contributors`）。推荐改成「**安装时从上游拉 surfcore + 本地缓存**」，你对外发布的只是一个安装器与设置中心。见 3.5。
3. **「用了别人的东西必须标出处」我做成机制而不是口号**：`third-party.json` 单一真相源 + 构建期闸门 + 安装向导「出处」页 + 设置页「关于」页 + 自动生成的 `NOTICE.md`。漏标 = 构建失败，合不进主线。

### 2.3 顺带发现的两个技术债（会卡住泛化）

- **状态根不统一**：代码默认写 `~/.dsh/surfcore/`，仓库里另有 `state/`，`~/.dsh/qq/` 还存着 `bridge.pid` / `mounted.json`。安装器必须明确「哪些随安装根、哪些固定在用户目录」，否则搬到别人机器上会读串。
- **`bridge.pid` 与实际进程不符**：pid 文件写 52004，`mounted.json` 写 27104，实际监听 3100 的是 54512。单实例锁必须重做，否则「双击第二次」会起两个 worker 抢端口。

## 3. 四条硬约束（先看这节再谈方案）

### 3.1 SnowLuma 不能打包进安装包

你 README 2.1 已经写死了这条：

> ⚠️ **SurfCore 不下载、不安装、不打包 SnowLuma**（EULA §5.4）。

安装器必须遵守自己已经承诺过的事。做法：**检测已装 → 没有就给官方 Releases 链接 + 一键打开浏览器 → 装完回填路径**。既不打包、也不代登录、不代扫码。

### 3.2 `@snowluma/sdk` / `@snowluma/mcp` 连许可证文件都没发布

这是「全部打包」最硬的一击，我实测了：

```
@snowluma/sdk  v1.14.22   license: "SEE LICENSE IN LICENSE"
  → node_modules/@snowluma/sdk/ 下没有 LICENSE 文件
  → package.json 的 files[] 里也没包含 LICENSE
```

也就是说：**它在 npm 上声明「许可证见 LICENSE」，但发布的包里没有那个 LICENSE。** 结果是任何人拿不到条款文本——既没法确认能不能再分发，也没法在 `NOTICE` 里正确署名。

结论：这两个包**只能装时从 npm 拉**（`npm ci` 不算我们再分发），绝不能进 zip。同一逻辑适用于整个 `node_modules`（98 个顶层包 / 26.1 MB）。

### 3.3 语音模型不能打包

`docs/VOICE-PACKS.md` 与 README 3.4 都写了：模型不进 GitHub，按各仓库 README 下载。GPT-SoVITS 系权重通常几百 MB 到 GB 级，且有独立的使用条款（**待核实**）。安装器只做「引导下载 + 校验 + 落位」。

### 3.4 现场证据：这台机器没有 git

```
PS> git -C E:\AI\surfcore remote -v
git : 无法将"git"项识别为 cmdlet...
```

你自己的 README 第 1 步就是 `git clone`。在没装 git 的 Windows 上，教程第一步就断了。所以分发形态必须是 **zip + 校验和**，不是「先装 git」。

### 3.5 归属判定：surfcore 是第三方项目（2026-10-31 核实）

| 证据 | 内容 |
|---|---|
| README | `git clone https://github.com/Mieksido/surfcore.git`（两处） |
| LICENSE 版权行 | `Copyright (c) 2026 Derpyu520 and qq-bridge / QSH contributors` |
| LICENSE 正文 | 「本项目（qq-bridge，将来的 QSH）采用 MIT 许可」——该 MIT 文本源自 qq-bridge |
| 体量 | v0.6.17 / 2026-10-28，148 个脚本、97 个测试、253 KB 控制台页 |

**两个结论：**

1. **MIT 允许再分发**，只要保留版权声明与许可原文。所以「随包」在法律上可行，不是禁区。但它同时把你变成 fork 维护者——上游 97 个测试、一周一版的节奏，你没有任何义务接这个盘。
2. **本项目的自我定位必须是「非官方安装器」**。不得用 SurfCore 的名字、图标、仓库名暗示官方身份；三处必须写明「非官方，与 SurfCore / qq-bridge / SnowLuma 作者无隶属关系」：安装向导首页、`NOTICE.md`、README 顶部。

你 **100% 拥有**的是：安装向导、设置中心外壳、STT 实现、出处机制。这些才是这个仓库真正的主体，也是唯一你能署名自己的部分。

**三选一（Q2′）：**

| 方案 | 做法 | 体积 | 合规 | 维护成本 |
|---|---|---|---|---|
| **A 下载式（推荐）** | 装时从上游拉指定版本 zip + sha256 | ~10 MB | 最干净：我们再分发的只有自己的代码 | 上游更新自动受益，只需改版本 pin |
| B 快照随包 | zip 内置一份 surfcore 快照，保留 MIT 原文 | ~40 MB | 合法（MIT），发版需逐项核对 | 你成为 fork 维护者 |
| C 混合 | 随包保底快照 + 默认查上游新版 | ~40 MB | 同 B | 两个真相源，最容易不一致 |

## 4. 产品形态

### 4.1 绿色版 + 浏览器 UI（已定）

不写注册表、不要管理员权限、不装服务。双击 → 本地起一个只监听 `127.0.0.1` 的小服务 → 自动打开浏览器 → 向导页。

理由：跨机器最稳、可被安全软件审计、和现有 `console.html` 是同一套技术栈、不需要代码签名也不会被 SmartScreen 拦。

### 4.2 双入口（已定）

```
                  ┌─────────────────────────────┐
   双击启动器 ───→ │  安装器 / 设置中心（本地 Web）│ ←── DSH 设置页「SurfCore」
                  └──────────┬──────────────────┘
                             │ 同一份 data/config.json + 同一套 API
                  ┌──────────▼──────────────────┐
                  │  bridge.js（单实例，:3100）  │
                  └──────────┬──────────────────┘
                             │ OneBot WS :3001 / HTTP :3000
                        SnowLuma ←→ QQ
```

要点：**两个入口读写同一份配置**，不各存一份。DSH 设置页已有的 14 个标签不重写，独立侧复用它的 API。

### 4.3 三个页面集合

| 页面集 | 什么时候出现 | 内容 |
|---|---|---|
| 安装向导 | 首次 / 修复 | 环境检测 → 出处与许可 → 选组件 → 配置 → 进度 → 自检 → 完成 |
| 设置中心 | 装完之后 | 概览 / QQ / 语音 / 记忆 / B站 / 额度 / 组件与更新 / 关于与许可 / 诊断 |
| 控制台 :3100 | 运行时 | 保持现状（10 个页面不动） |

## 5. 安装流程（状态机）

每一步落盘证据到 `data/install.log` + `data/manifest.json`，中断后从断点续，不从头再来。

| 步 | 名称 | 做什么 | 失败时 |
|---|---|---|---|
| S0 | 环境检测 | OS 版本 / Node≥22.13 / DSH 是否存在及版本 / 端口 3000·3001·3100 占用 / 已装版本 / `~/.dsh` 可写 / 网络 | 红项不拦「继续」，但拦「下一步」直到勾「我知道风险」 |
| S1 | 出处与许可 | 列出**所有**将要用到的上游组件、作者、仓库、许可证、我们的修改；必须滚到底并勾选 | 不勾不能继续（合规闸门） |
| S2 | 安装位置 | 安装根目录（默认 `%LOCALAPPDATA%\SurfCore`）+ 状态目录（固定 `~/.dsh/surfcore`，不可改） | 路径含空格/中文 → 警告不拦 |
| S3 | 选组件 | 功能矩阵（第 6 节）；勾父项自动带子依赖；冲突即时标红 | 缺依赖 → 灰掉并说明原因 |
| S4 | 配置 | QQ 号、白名单群/人、SnowLuma 地址与 token、控制台 token | 可整体跳过（装完再配），但会提示「跳过后不会自动回消息」 |
| S5 | 下载与安装 | 逐组件：下载 → sha256 → 解压 → `npm ci` → 写 manifest | 单点重试 3 次；全失败则停在该项，其余继续 |
| S6 | 注册 DSH | preset + 3 个 MCP + bundle（复用 `setup-dsh.mjs`，幂等） | 未装 DSH → 跳过并提示「以后可在设置中心补注册」 |
| S7 | 自检 | 6 项：配置合法 / 端口可用 / 网关可达 / DSH 注册完整 / 工具可见 / 存储可写 | 出报告 + 每条给修复动作，不假装成功 |
| S8 | 完成 | 启动桥接、打开设置中心、导出安装报告（脱敏） | — |

**回滚**：S5 中途取消 → 删除本次新建目录 + 还原 `config.json` 备份；**绝不碰** `~/.dsh/surfcore` 里已有的 characters/memory。

## 7. 目录设计

```
<安装根>\
  start.bat                    ← 启动器：起服务 + 开浏览器
  安装器\                         ← 本项目自有代码（MIT）：server + web + lib
  installer\sources.json         ← 上游版本 pin（tag / commit / sha256）
  app\                           ← 装时从上游拉的 surfcore（不在本仓库里）
    src\ dsh\ plugins\ scripts\ public\ roles\ examples\
    package.json  config.json    ← config.json 是真相源（上游所有读写都指这里）
    node_modules\                ← 装时 npm ci（约 33 MB）
  runtime\
    npm\                         ← 系统没有 npm 时下载到这里
    node\                        ← 发布包内置 Node（见 Q4）
  cache\                         ← 下载缓存（surfcore-<tag>.tar.gz）
  data\
    manifest.json                ← 装了什么 / 版本 / sha256 / 来源 URL
    config.bak\<时间戳>.json     ← 配置备份（升级/修复前自动留）
    install-state.json           ← 向导进度（原子写）
  NOTICE.md  THIRD-PARTY.md  LICENSE
```

> **为什么 config 在 `app\` 而不是 `data\`**：上游所有代码都按 `ROOT/config.json` 读，
> 而且它自己会回写（token 自愈、控制台改白名单）。放在 `data\` 只会变成一份没人读的影子副本。
> 代价是升级时 `app\` 会被换掉，所以安装器在换目录前把旧 config 捞出来、合并后再写回（已实测）。

**固定不随安装根走的**（沿用现有约定，避免把老用户的记忆搬坏）：

```
~/.dsh/surfcore\        ← characters / memory / bili / pet / backups
```

## 8. 出处与许可（按你新加的要求，做成机制）

### 8.1 三条硬规则

1. **没登记 = 不许进包**：任何代码/模型/二进制进入安装包或下载清单，必须在 `third-party.json` 有对应条目。构建脚本扫描 `package.json`、下载清单、`plugins/` 目录，发现未登记的依赖 → **构建失败**。
2. **不标注不许上线**：`NOTICE.md` 由脚本从 `third-party.json` 生成，**禁止手改**（文件头写「本文件为生成物」）。
3. **引用别人的说明不等于拥有它**：像 playbook 那种「作者明确说只放链接」的，只放链接与设计说明，**不复制正文**。

### 8.2 单一真相源 `third-party.json`

字段（每条）：

```jsonc
{
  "id": "qq-bridge",
  "name": "qq-bridge",
  "upstream": "https://github.com/Derpyu520/qq-bridge",
  "author": "Derpyu520",
  "license": "MIT",
  "licenseUrl": "https://github.com/Derpyu520/qq-bridge/blob/main/LICENSE",
  "inclusion": "reference",   // bundle | download | user-provided | reference | doc-only
  "usedFor": "桥接层结构参考（收发队列、单实例、控制台）",
  "modified": "重写并拆分进 src/bridge.js；协议层改为直接对接 @snowluma/sdk",
  "versionPin": "—",
  "notice": "本项目为独立实现，未复制其源码；设计思路来源已注明。"
}
```

`inclusion` 五种，各自的义务：

| 值 | 含义 | 义务 |
|---|---|---|
| `bundle` | 随安装包分发 | 附完整 LICENSE 原文 + 我们的修改说明 |
| `download` | 安装时从上游拉 | 向导里展示出处；日志记录 URL + sha256 + 版本 |
| `user-provided` | 用户自备 | 只给指引链接，不代下载、不代登录 |
| `reference` | 参考设计，未复制源码 | NOTICE 注明「参考」 |
| `doc-only` | 只引用文档 | 只放链接，不复刻正文 |

### 8.3 三个消费点（同一份数据，三种呈现）

1. **安装向导 S1「出处与许可」页**：分组列出，每行「名称 · 作者 · 仓库 · 许可证 · 用途 · 我们改了什么」，可点开原文。
2. **设置中心「关于与许可」页**：安装完成后随时可查，含版本 pin 与下载来源 URL。
3. **仓库根 `NOTICE.md`**：由 `scripts/gen-notice.mjs` 生成，随包分发。

### 8.4 已经踩到的三颗雷（都已在上面验证）

| 雷 | 证据 | 处置 |
|---|---|---|
| SnowLuma 主程序 | 你 README 引 EULA §5.4 | `user-provided`，绝不打包 |
| `@snowluma/sdk` / `@snowluma/mcp` | `license: "SEE LICENSE IN LICENSE"`，但 npm 包里**没有 LICENSE 文件** | `download`（npm ci），不进 zip；在 NOTICE 里如实写明「上游未随包提供许可证文本」 |
| playbook 文档 | 作者声明「只放链接和设计说明」 | `doc-only`，只放链接 |

### 8.5 还有两处待核实（我不敢替你写许可）
